How a query reads the disk

One vector takes 952 bytes on disk. A query barely touches the biggest part.

  • Time column8B
  • Id, id hash, bloom27B
  • Posting lists45B
  • 1-bit code100B
  • int8 vector772B

  1. Skip by time

    Segments are bucketed by day, so a time filter drops whole segments unread.

  2. Turn the filter into a bitset

    Posting lists become a bitset of matching rows, with MongoDB’s multikey rules.

  3. Score 1-bit codes

    Every matching row for a narrow filter; the nearest IVF lists for a broad one.

  4. Rescore with int8

    Only the top candidates read their int8 vectors. MongoDB fetches the documents.

Alongside MongoDB

MongoDB stays the record; the index can be dropped and rebuilt.

Pipeline rewrite

try
{
  var rewritten = MongoVectorSearch
    .RewritePipeline(
      engine, pipeline, out _);
  var docs = await items
    .Aggregate<BsonDocument>(rewritten)
    .ToListAsync();
}
catch (FilterNotSupportedException)
{
  // fall back to MongoDB
}

One stage replaced

The first stage becomes a $match on ids; the rest runs unchanged.

Unsupported filters fall back

They throw, and the original pipeline runs on MongoDB.
